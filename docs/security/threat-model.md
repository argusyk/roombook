# Модель загроз RoomBook (STRIDE)

Документ живий: кожна нова загроза додає рядок, кожна нова межа довіри – розділ.

## Межі довіри (DFD)

| № | Межа | Що через неї проходить |
|---|---|---|
| 1 | Користувач → API | `purpose` бронювання, тексти форм (недовірений вільний текст) |
| 2 | Репозиторій/issue → агент | AGENTS.md, код, тексти issue і PR, журнали CI (недовірені для агента) |
| 3 | Агент → інструменти | shell у пісочниці, MCP `roombook_db` (поза пісочницею, права ролі `roombook_ro`), вебпошук |
| 4 | CI → GitHub | `GITHUB_TOKEN`, секрет `CODEX_API_KEY`, гілки й PR |
| 5 | Агент → постачальник моделі | контекст сесії (код, дані з бази, журнали) |

## Канарка

Перевірка ін'єкції без шкоди: `tools/security/canary.sql` (лише тестова база,
користувач 9001), запуск `codex exec -p report "…через скіл db-report"`, оцінка –
`tools/security/check-canary.sh <звіт>`.

## Ключ витік: процедура

1. Відкликати ключ у консолі постачальника і випустити новий.
2. Оновити секрет `CODEX_API_KEY` у GitHub Actions і на машинах, де він був.
3. Переглянути журнали використання API й аудиту за період від можливого витоку.
4. Записати інцидент і перевірити процедуру на навчальному ключі.

## Чекліст команди

1. Пісочниця `workspace-write` без мережі – типовий режим; мережа лише через `deps`.
2. Профіль `safe` для чужого й legacy-коду; `report` – для звітів з бази.
3. MCP: зафіксовані версії, мінімальні `enabled_tools`, роль бази без персональних даних.
4. Правила команд: `push`, `clean`, `reset --hard` – `prompt`; `docker` – `forbidden`.
5. Вільний текст користувачів і issue – дані, а не інструкції (промпти це кажуть явно).
6. Перевірка результату агента – поза агентом (тести, test-guard, заборонені шляхи).
7. CI: `permissions` мінімальні, ключ лише в кроці агента, без `pull_request_target`.
8. Організація: `requirements.toml` забороняє `danger-full-access` і `never`, вебпошук `cached`.
9. Сканування секретів у CI і push protection.
10. Процедура для витоку ключа (вище).
11. MCP-сервери – оновлення через рев'ю.
12. Зовнішні PR – людське рев'ю; агентне – лише без секретів.
