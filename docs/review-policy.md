# Політика рев'ю коду RoomBook

1. Перед кожним push автор запускає `/review` проти `main` у профілі `safe`
   (`codex -p safe`, пресет «against a base branch») і виправляє знайдене або
   пояснює в описі PR, чому не виправив.
2. Кожен PR отримує автоматичне рев'ю Codex у GitHub. Коментар `@codex fix`
   дозволено лише поза ризиковими зонами.
3. Зміни в міграціях і схемі БД, в автентифікації та в `legacy-php/` вимагають
   схвалення власника зони з `.github/CODEOWNERS`. Для змін автентифікації
   додатково запускається `@codex security review`.
4. Решта PR потребує одного схвалення будь-кого з команди. Агент не схвалює PR ніколи.
5. Кожен коментар агента автор позначає реакцією (👍 корисний / 👎 хибний) для
   статистики точності (`tools/review/precision.sh`), а пропущені дефекти отримують
   мітку `missed-by-review`.

Захист гілки `main`: обов'язковий PR, схвалення власників коду, зелені перевірки CI.
Правила для рецензента-агента – `## Code Review Rules` в `apps/api/AGENTS.md`,
бізнес-правила – `docs/domain-rules.md`.
